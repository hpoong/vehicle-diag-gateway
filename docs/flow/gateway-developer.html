03 / CANONICAL HASH

표현이 달라도 의미가 같으면 같은 hash

DiagnosticResultNormalizer · UtcTime.MILLIS

정규화

occurredAt → UTC 밀리초 3자리. ECU는 ID 순, DTC는 값 순 정렬.

직렬화

고정된 canonical map을 JSON으로 직렬화하고 UTF-8 SHA-256 계산.

인덱스 보존

ECU의 requestIndex는 hash·전송 본문에서 제외하고 오류 위치에 사용.

swVersion의 생략과 null을 동일하게 취급합니다. sessionId는 hash에 포함하지만 receiver 본문에는 포함하지 않습니다.

04 / RULES

공통 규칙은 모든 브랜드에 강제됩니다

CommonRuleValidator → PolicyRegistry.resolve(brand).validate(command)

계층조건응답
C1 / C2ECU 0건 / occurredAt > now + 5분422 common-rule-violation
C3 / C4ECU ID 중복 / ECU 내 DTC 중복같은 단계의 위반 전체 반환
BRAND_A-v1swVersion == null422 policy-violation + policyCode
STANDARD-v1등록되지 않은 브랜드의 기본 정책추가 브랜드 위반 없음

PolicyRegistry는 브랜드 중복·기본 정책 누락/중복이면 기동 실패. +5분 경계는 통과합니다.

05 / TRANSACTION

쓰기 트랜잭션은 별도 Spring 빈에 둡니다

IngestWriter.save · @Transactional(rollbackFor = Exception.class)

01① result

ON CONFLICT DO NOTHING RETURNING

02② observations

정렬된 DTC → text[]

03③ latest

ECU ID 순 조건부 UPSERT

04④ outbox

고정 payload + UUID INSERT

Service (트랜잭션 밖)
  └─ Writer proxy → BEGIN → ① → ② → ③ → ④ → COMMIT
                         └─ 어느 단계든 실패 → ROLLBACK

INSERT RETURNING 매핑: affectData=true, flushCache=true. DB now()를 수신 시각으로 사용합니다.

06 / RACE

동일 요청 5개가 경합해도 신규는 1개

고유 키 충돌을 예외로 처리하지 않고 INSERT 결과 유무로 분기합니다.

요청 A요청 B~E
사전 조회: 없음사전 조회: 없음
고유 키 확보 → 결과·관측·latest·outbox 저장INSERT에서 경쟁 트랜잭션 완료 대기
COMMIT → ACCEPTED (202)DO NOTHING → writer 종료
결과 ID R기존 키 재조회 → DUPLICATE (200), 같은 R

서로 다른 내용이면 후속 재판정에서 409입니다. 재조회는 writer 트랜잭션 밖이며, 승자가 커밋한 행을 읽습니다.

07 / LATEST

최신값은 시각과 결과 ID의 튜플로 비교합니다

잠금 순서는 ecuId 오름차순으로 고정합니다.

ON CONFLICT (vin, ecu_id) DO UPDATE
SET result_id = EXCLUDED.result_id,
    occurred_at = EXCLUDED.occurred_at,
    dtc_codes = EXCLUDED.dtc_codes, updated_at = now()
WHERE (vehicle_ecu_latest.occurred_at, vehicle_ecu_latest.result_id)
    < (EXCLUDED.occurred_at, EXCLUDED.result_id)
영향 행 0

과거 관측이면 정상. 이력과 outbox는 그대로 저장합니다.

빈 배열

고장코드 없음도 유효 관측. 최신 DTC를 빈 배열로 갱신합니다.

08 / RECEIVER CONTRACT

전송 payload는 접수 시 한 번만 생성합니다

OutboxPayloadFactory → OutboxMapper.insert

eventId: 앱 생성 UUID = outbox_event.event_id
source: { system: "diag-gateway", resultId,
          deviceId, deviceEventId, policyCode }
vin, brand, occurredAt, receivedAt, ecus
시간: UTC yyyy-MM-ddTHH:mm:ss.SSSZ
포함·제외

ECU ID 순서. 없는 swVersion은 키 생략. sessionId·requestIndex 제외.

저장 보장

payload.eventId 일치 CHECK. 초기 PENDING / 0회 / cycle 1. 직렬화 예외도 전체 롤백.

09 / HTTP CONTRACT

성공은 data, 오류는 ProblemDetail

신규 202 · 중복 200 · 충돌 409 · 업무 검증 422

{ "data": {
  "resultId": 7, "deviceId": "device", "eventId": "event",
  "status": "ACCEPTED", "policyCode": "STANDARD-v1",
  "receivedAt": "2026-11-07T00:00:00.120Z",
  "delivery": { "eventId": "<UUID>", "status": "PENDING" }
}}

중복 응답의 policyCode·수신 시각·전송 UUID는 기존 저장 값입니다. 전송 상태는 현재 DB 조회 값입니다.

10 / QUERY

없으면 404 not-found
