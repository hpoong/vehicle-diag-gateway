03 / CANONICAL HASH

표현이 달라도 의미가 같으면 같은 hash

DiagnosticResultNormalizer · UtcTime.MILLIS

정규화

occurredAt → UTC 밀리초 3자리. ECU는 ID 순, DTC는 값 순 정렬.

직렬화

고정된 canonical map을 JSON으로 직렬화하고 UTF-8 SHA-256 계산.

인덱스 보존

ECU의 requestIndex는 hash·전송 본문에서 제외하고 오류 위치에 사용.

swVersion의 생략과 null을 동일하게 취급합니다. sessionId는 hash에 포함하지만 receiver 본문에는 포함하지 않습니다.

15 / OUTCOME & BACKOFF

결과 분류와 백오프가 다음 상태를 결정합니다

OutcomeClassifier → BackoffPolicy → DeliveryRecorder

입력시도 결과다음 상태
2xxSUCCESSSENT
408 / 429 / 5xx / 연결 실패RETRYABLE한도 미만 PENDING, 한도 도달 DEAD
응답 타임아웃 / 기타 I/OUNCERTAIN한도 미만 PENDING, 한도 도달 DEAD
그 외 HTTP (409 포함)NON_RETRYABLEDEAD · NON_RETRYABLE
기타 예외UNCERTAIN · UNEXPECTED_ERROR재시도 / 한도 도달 DEAD

raw = min(5초 × 2^(시도 번호−1), 5분), equal jitter = raw/2 ~ raw. 기본 한도는 10회입니다. 선점 직후 한도를 초과하면 HTTP 없이 SKIPPED_MAX_ATTEMPTS를 기록하고 DEAD로 종료합니다.

16 / LEASE & STALE

lease 회수 후 늦은 결과는 상태를 덮어쓰지 않습니다

정합성은 선점 토큰으로 보호합니다.

순서outbox / 시도 이력
T1 선점 후 처리 중 종료PENDING, STARTED(T1)
lease 만료 후 T2 선점새 토큰 T2, ABANDONED(T1) → STARTED(T2)
T1 결과가 늦게 도착outbox UPDATE 0행 → STALE, ABANDONED 시도의 late_outcome 최초 1회 기록
T2 정상 결과 기록현재 토큰 일치 → SENT / PENDING / DEAD

lease만 만료되고 재선점되지 않았다면 T1은 정상 기록할 수 있습니다. 회수 시 이전 STARTED 종료를 새 INSERT보다 먼저 실행해 outbox당 STARTED 최대 1개 제약을 지킵니다.

19 / AUDITED REQUEUE

DEAD 재처리와 감사 기록을 함께 커밋합니다

POST /ops/events/{outboxId}/requeue

X-Operator: kim.ops
{ "reason": "receiver 점검 종료 확인 후 재처리" }

DEAD → PENDING · attempt_count=0 · cycle_no+1
next_attempt_at=now() · DEAD/선점 필드 초기화
조건부 갱신

DEAD 행 잠금·UPDATE 후 ops_action_log INSERT를 같은 트랜잭션에서 처리합니다.

동시성·롤백

동시 요청은 한 건만 200, 나머지는 409. 감사 INSERT가 실패하면 상태 변경도 롤백합니다.

이력 보존

이전 실패 요약·시도 이력은 유지합니다. 다음 선점은 새 cycle의 attempt 1로 시작합니다.

X-Operator는 필수·공백 불가·최대 64자. reason은 10~500 Unicode 문자이며 NUL·공백만·비문자열은 400입니다. 없는 ID는 404, DEAD 이외 상태는 409입니다. 감사 기록에 requestId를 보관하며 사유는 애플리케이션 로그에 남기지 않습니다.
